## Architecture and local setup

- **Frontend.** React 19 and Vite 8. [`src/App.jsx`](../src/App.jsx) owns the shell, auth and shared state. [`src/features/`](../src/features/) contains Matchday, player, Admin, and Clubs views. [`src/lib/api.js`](../src/lib/api.js) supplies API auth headers, GET caching, and request deduplication for its callers.
- **Backend.** Node 24 and Express 5. [`server/app.js`](../server/app.js) mounts routes and middleware. [`server/server.js`](../server/server.js) connects MongoDB and starts scheduled jobs. Firebase Authentication supplies identity and Firebase Admin verifies tokens. Ratings, statistics, and Clubs economy logic live on the server. Gemini editorial generation is optional. See the [architecture guide](architecture.md) and [Clubs rules](v3-clubs-spec.md).
- **MongoDB.** The V4 Render service uses the dedicated `gg-matchday-v4` Atlas cluster. The core database is `gg_matchday_v4`, and `CLUBS_DB_NAME` selects `gg_matchday_v4_clubs` for the separate Clubs connection. Render's connection targets and the Atlas user's database and cluster scopes were checked on 20 November 2026. Verify the targets again if configuration changes. Keep production backup and Atlas credentials out of V4. See [database operations](database-operations.md).
- **Local development.** Use Node 24, run `npm ci`, and follow [`.env.example`](../.env.example) and the [README](../README.md) with local or V4-only credentials. Run `npm start` for the API on port 5000 and `npm run dev` for Vite. Use a MongoDB replica set for transaction-dependent flows. Playwright starts its own isolated database with fixtures and test-only authentication.

## Live profile approvals

Profile administration lists unlinked player accounts. The API excludes administrator roles and the configured administrator email and blocks direct linking attempts for either. Each eligible account stores one player ID, and a player can be linked to several accounts. The V4 API removes the legacy unique index for this field on startup in `gg_matchday_v4`.

1. A linked user submits a profile change. Profile Administration approves it through the server's admin-only route in [`server/routes/profileRequests.js`](../server/routes/profileRequests.js).
2. The API commits the player and approval together in a MongoDB transaction, then emits `profile-updated` over [`GET /api/live/profile-updates`](https://gg-matchday-v4-fresh-api.onrender.com/api/live/profile-updates). A concurrent approve and reject yields one decision. The event carries only the public player ID. The stream checks persisted approvals every three seconds while it has subscribers so another API instance can observe an approval.
3. After API success, [`ProfileRequests.jsx`](../src/ProfileRequests.jsx) clears the pending row and shows confirmation. The approving tab also receives a local event. [`src/lib/profileLive.js`](../src/lib/profileLive.js) listens for both signals and invalidates player reads. Open profile and roster views fetch the affected player's current record. Reconnect, online, and foreground checks reconcile the player list, with a 20-second fallback while a visible page is disconnected.
4. The [Playwright regression](../tests/e2e/profile-live.spec.js) submits and approves a fixture via the API and checks that two independent viewer sessions update without a page reload. For a preview acceptance check, use a V4 test player and admin session, approve through the Admin UI, and confirm the pending row, a second open profile, and recovery after disconnect. A signed-in approval against the hosted preview was outside this documentation handoff.

## Live data and performance

- The desktop Matchday welcome shows only the bottom-left **PRESS TO CONTINUE** prompt while the entry video is absent. After startup on mobile, **Enter Fullscreen** requests fullscreen for the entire document. Browsers that decline the request offer **Continue in browser**. Set `VITE_MATCHDAY_INTRO_VIDEO` on the frontend to add a muted background video to both entry screens. The mobile prompt dims the video.
- The stadium video starts during Matchday startup and resumes in the workspace. It pauses at the entrance prompts, in Clubs, in a hidden browser tab, with reduced motion, and during a page swipe. This is separate from the optional walkout video.
- Home renders Players, Matches, Goals, and Seasons as native buttons. Goal Leaders fetches on open. Player Comparisons uses the shared roster, and opening the preferred-position editor uses the current profile and its ID. Saving a player or approved positions still triggers the live refresh.
- Loading the next archive page keeps already loaded pages and requests only missing pages. A failed read keeps the existing list visible and retries the missing page before advancing. A Matchday data refresh reloads the visible archive and totals. Home reads six news items, matching its display limit. Calendar warms the match-detail module when visited.
- Dialogs retain keyboard focus while forms rerender and return focus when closed.
- The comparison against V3 `main` at `c78e25c` found all 144 static Express route and mount registrations in V4. V4 uses the V3 scrolling player profile layout and section order. Local desktop and mobile browser suites cover Matchday, Clubs, profile approvals, and rating disputes using independent fixture databases. Google sign-in and provider-backed AI require credentials for a hosted check.

- Matchday Signature shares matte tab selections, subtle waves and etched GG marks with Clubs. Dark uses dusty lavender accents on navy and plum. Gold pairs burnished gold controls with muted sage details. Mobile uses a compact Home layout and desktop retains the V3-style layout and stadium media. Player profiles open at the identity header and use the V3 single-page layout.
- Matchday and Clubs share the Signature palette for base surfaces, raised controls, text and borders. Starting XI offers Pitch and List views of the same formation, common formation shortcuts, and direct player profile access. Returning from a player profile restores the lineup and scroll point. Leaderboard filters stay visible while scrolling and keep the previous results visible until the new filter returns.
- On phones, Matchday uses a single row for the Home stats and Leaderboard podium. Account actions sit next to the avatar when there is room. Match Record can filter the roster by name while retaining all team selections and totals. The Clubs credit fills the available space below short tabs, and moves with the content on long tabs. The stadium video pauses while Clubs is open.
- The player video, portrait and style badges share the profile banner. Authorized editors use Edit Profile, and linked viewers can request changes from the banner. The signed-in account avatar opens appearance settings and access to the linked player profile from any Matchday tab. Admin account settings show account details and appearance controls.
- Matchday and Clubs dialogs use the selected theme's matte surfaces and a short entrance. Clubs adds motion to its header, controls and mobile menus while keeping the swipe pager ready. Reduced-motion settings disable these effects.

- Matchday and Clubs remember each tab’s scroll position while the app is open. The URL records the selected tab so links reopen that destination and browser Back and Forward follow tab navigation. Clubs destinations still follow the viewer’s existing access rules.
- Mobile swipe previews use the destination tab's saved scroll position before the tab becomes active. The startup splash waits up to 1.8 seconds for the session. If the check is still pending when fullscreen entry finishes, Matchday opens and shows the check in the account bar. Dark uses the original V3 icon and Gold uses the V4 gradient icon, including on reload.
- Account checks time out after 15 seconds. A newer Firebase identity cancels the previous check and clears its role while the new account loads.

- Matchday keeps neighboring mobile tabs laid out and refreshes the primary tab data while the workspace is open. The mobile Matchday and Clubs dock highlights settle on the selected tab when a drag is released. The Matchday background video holds its frame during horizontal gestures and resumes after navigation settles, subject to the device's reduced-motion preference.
- V3 moves a single stage on touch. The V4 pager keeps the incoming page visible during the drag and moves only the two pane transforms per frame. It accepts shorter deliberate horizontal drags, keeps native vertical scrolling, and settles the drag in 95 ms. Native-touch browser tests cover a short drag and a second drag begun before the first has settled.

- Match records, rankings, calendar history, open match details, player statistics and awards, and news refresh from saved data. Clubs views refresh fixtures, formation, market, reviews, administration, and wallet data. Chat and notifications refresh for signed-in users. The existing `CHAT_ENABLED` setting controls chat availability.
- [The server](../server/services/liveData.js) watches selected MongoDB collections and sends refresh topics without records or identifiers on the public and authenticated streams. [The client](../src/lib/liveData.js) invalidates matching reads so active views use the normal APIs and access checks. It reconciles after reconnect, and uses bounded retries for outages.

## Clubs workspace

- Clubs uses a desktop navigation rail and a mobile dock. Match lists show confirmed upcoming fixtures and results. Linked squad members can switch to My Fixtures. Current captains submit fixture requests and handle decisions in the captain inbox. Pending requests and captain votes stay out of the public fixture response.
- Betting shows confirmed eligible fixtures and a player's open and settled bets. V4 allows squad members to bet on their own Club's fixtures using existing in-game credits. Limits, fixture deadlines, wallet debits, payouts, and refunds remain server-controlled. Bet history is scoped to the signed-in player and fetched in pages.
- Open and settled bet history stays available when the wallet read fails. The scouting card's Make Offer shortcut opens Market with the selected player and records the destination in browser history.
- My Player brings together the private wallet, personal and Club rewards, and Club career records. The header opens the linked account's full Matchday player profile. Players request edits from their own profile. Account linking and approval of profile edits are under Matchday Admin → Profile administration.
- Clubs Admin uses the Matchday Admin layout with Clubs styling. The grouped sidebar opens Dashboard, Applications, Clubs, Matches, Action queue, and Activity & audit. Desktop keeps navigation visible beside a separately scrolling work area. On mobile, Sections opens the sidebar drawer. The dashboard has shortcuts to active workflows and recent Club records, and Matches can be searched by Club, date, or record ID.
- The [Clubs workspace browser test](../tests/e2e/clubs-workspace.spec.js) checks captain and member views in independent sessions, a same-Club bet, private history, and a cancellation refund against isolated fixtures.

## GG Companion foundation

- Leaflet's [PipWorld](https://github.com/itsadithyakv/Leaflet-BookReader/blob/main/apps/src/components/PipWorld.tsx) and [PipSay](https://github.com/itsadithyakv/Leaflet-BookReader/blob/main/apps/src/components/PipSay.tsx) were the interaction references. GG Matchday has its own surfaces, styling and movement code.
- Add `companion=preview` to a V4 Matchday or Clubs URL to load the test companion. Drag and release it to try landings, mobile edge rebounds and desktop rail slides. Activate it to alternate between standing and sitting and show a speech bubble. The preview loads on demand.
- The world reads the active workspace and the topmost open dialog. It uses the visible top edges of headers, navigation, cards and sections as surfaces. Inactive tabs and clipped or hidden elements are excluded. Add `data-companion-surface="unique-name"` to an element to give it a stable target, or use `data-companion-surface="off"` to exclude a subtree.
- The Phase 2 controller can dispatch `gg:companion` custom events on `window` with `detail: { type: "move", target, pose }`, `{ type: "pose", pose }` or `{ type: "say", text, duration }`. A target can be a visible element or its surface name. Supported poses are `stand`, `sit` and `celebrate`. A line of dialogue uses plain text and a duration in milliseconds.

## Matchday Signature motion

- New destinations inside `SwipePager` inherit the same page entrance on taps and keyboard navigation. Swipe arrivals use the pager animation and its saved scroll coordinates. Standalone pages can use `data-signature-page-enter`. Shared durations, easing and the Dark and Gold treatments live in [`matchday-motion.css`](../src/matchday-motion.css).
- Use the shared `Modal` for dialogs. It supplies the scrim, panel motion, keyboard dismissal and focus restoration. Use the same motion tokens for small menus and drawers. Reduced-motion settings skip the workspace shutter and page or dialog movement.
- The Clubs and Matchday workspace shutter covers the current page before navigation. It holds the new page behind the opaque panels for a beat before revealing it. Keep the longer transition for workspace changes so primary tabs and controls stay quick.
- The pitch and substitutes use the same player card. The bench follows the pitch touchline on desktop and scrolls sideways below the pitch on phones, with one seat per available substitute.
- References include [Sportening's lineup](https://dribbble.com/shots/15394948-Sportening-Football-lineup-and-stats), [The Guru Fox's pop-up overlay](https://dribbble.com/shots/27409033-Pop-up-Overlay-Daily-UI-Challenge-016), [Fluent 2's motion guidelines](https://fluent2.microsoft.design/motion) and [IFAB's technical area markings](https://www.theifab.com/laws/latest/the-field-of-play/#the-technical-area).
